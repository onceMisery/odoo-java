# A到B演进路线

## 1. 文档控制
- 文档编号：ROADMAP-ODJ-08
- 版本：v1.0
- 状态：待评审
- 关联文档：`docs/03-接口设计-API清单与契约.md`、`docs/07-MVP里程碑与验收标准.md`

## 2. 演进目标
- A 阶段：交付可用元数据平台（可上线最小闭环）。
- B 阶段：逐步对齐 Odoo 核心语义，增强兼容性与生态承载能力。

## 3. 演进策略
- 原则：小步快跑、可回滚、可量化验收。
- 方法：每个增强能力都遵循“设计评审 -> PoC -> 灰度 -> 全量”。

## 4. 路线图

### B1：Domain 解释器增强（最高优先级）
A 现状：`= != > >= < <= in like ilike` + AND。
B 目标：
- 支持 `|` OR、`!` NOT。
- 支持关系字段点号访问（如 `partner_id.name`）。
- 支持 `child_of`（推荐 closure table/path，避免硬递归）。
- 支持 `any/not any`（EXISTS 子查询）。

退出标准：
- Domain 回归用例覆盖核心运算符，SQL 结果与预期一致。

### B2：Record Rule 完整逻辑
B 目标：
- global rules 交集、group rules 并集语义对齐。
- 规则编译缓存，key 包含 `model+uid+allowed_company_ids+groups+lang`。

退出标准：
- 权限回归通过；跨角色、跨公司无越权。

### B3：字段 groups 与 UI/ORM 强一致
B 目标：
- `fields_get` 不返回无权限字段。
- `get_view` 剔除无权限字段和按钮。
- `read/write` 对无权限字段显式拒绝。

退出标准：
- API 与 UI 可见性一致性测试通过。

### B4：视图继承与 XML 合并
B 目标：
- 支持 `inherit_id + xpath + position`（before/after/replace/inside）。
- 合并结果按 `view_id + groups + lang` 缓存。

退出标准：
- 视图继承冲突可检测并给出可读错误。

### B5：QWeb + 报表 PDF
B 目标：
- 实现 QWeb 最小子集：`t-if/t-foreach/out/t-att/t-field`。
- 使用 `wkhtmltopdf`，具备进程池与超时回收机制。
- 新增 `ir_actions_report`。

退出标准：
- 关键业务报表稳定生成，失败可观测可重试。

### B6：多公司语义 + JSON-2 完整对齐
B 目标：
- 打通 `allowed_company_ids` 全链路。
- 完整提供 `/json/2` 读写接口与错误语义。

退出标准：
- 外部系统可仅通过 JSON-2 完成主要集成，不依赖 `/web/*` 私有契约。

## 5. 风险与应对
- 风险：动态 DDL 导致锁等待与发布风险。
  - 应对：严格执行 Expand/Contract + 低峰发布 + 预演。
- 风险：权限语义偏差导致越权。
  - 应对：引入权限基准用例库，强制回归门禁。
- 风险：兼容目标膨胀拖慢交付。
  - 应对：坚持 A 阶段边界，不承诺完整 addons 生态兼容。

## 6. 预算与资源建议（评审输入）
- 研发：后端 3-5 人，前端 1-2 人，测试 1-2 人，DevOps 1 人。
- 节奏：2 周一个迭代，里程碑按 12 周 A 阶段执行。
- 工具：性能压测、契约测试、数据库变更审计平台。

## 7. 治理机制
- 架构评审：每个 Bx 子阶段立项评审一次。
- 变更管理：接口/DDL 变更必须附回滚方案。
- 发布门禁：无自动化报告不允许进生产。
