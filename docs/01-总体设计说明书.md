## 2. 背景与目标
- 背景：对标 Odoo 的模块化 ERP 平台，采用 Java 技术栈重构，优先保障可交付与可演进。
- A 阶段目标：交付最小闭环（登录、元模型、CRUD、权限、最小视图、模块安装）。
- B 阶段目标：逐步增强 Odoo 核心语义兼容（Domain、Rule、视图继承、QWeb、JSON-2）。
- 非目标：A 阶段不承诺完整 addons 生态兼容与多公司语义完全对齐。

## 3. 范围与边界
- 范围内：
  - `/web/*` JSON-RPC 兼容入口。
  - `/json/2/*` 最小兼容桥。
  - 模块化单体架构 + Dubbo 接口化。
  - 核心元数据与权限模型。
- 范围外：
  - 完整 Odoo ORM 高级语义（prefetch/computed/related 全量）。
  - 全量 QWeb 与报表生态。

## 4. 总体架构
- 组件：Gateway、Platform、MySQL、Redis、Nacos、Sentinel。
- 架构模式：模块化单体（部署）+ 服务接口化（演进）。
- 调用链：HTTP(JSON-RPC/JSON-2) -> Service -> ORM -> MySQL。
- 设计原则：协议层与业务层解耦，便于兼容与替换。

## 5. 核心能力设计
### 5.1 协议层
- JSON-RPC Dispatcher 统一解析、错误映射、上下文注入。
- JSON-2 与 JSON-RPC 共用服务层，避免重复实现。

### 5.2 元数据与模块
- 元数据：`ir_model`、`ir_model_field`、`ir_ui_view`、`ir_actions_act_window`。
- 模块安装：`module.yml` + XML/CSV，依赖拓扑排序执行。
- 幂等导入：基于 `ir_model_data(module,name)`。

### 5.3 数据访问与权限
- ORM 基于 jOOQ 动态 DSL。
- ACL + Record Rule 注入查询条件。
- 字段级权限在 `fields_get/get_view/read/write` 保持一致。

### 5.4 动态 DDL 治理
- 锁表：`ir_schema_lock`。
- 版本表：`ir_schema_version`。
- 策略：Expand/Contract，禁止直接破坏式迁移。

## 6. 非功能要求
- 性能：关键查询具备 P95 指标。
- 安全：Session Rotate、CSRF、登录限速。
- 可观测：日志、指标、链路追踪。
- 可运维：支持灰度、回滚、容量评估。

## 7. 风险与约束
- 风险：动态 DDL 与权限语义偏差。
- 约束：A 阶段单公司模式，B 阶段再做强一致多公司。
- 应对：回归基准用例 + 变更门禁。
